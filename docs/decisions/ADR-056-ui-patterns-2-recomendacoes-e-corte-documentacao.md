# ADR-056 — UI Patterns 2 como contrato de apresentação e corte orientado por evidência

- **Status:** aceita pelo responsável em 2026-11-13.
- **Escopo:** tema `aculta420_v2`, componentes SDC e suas integrações de apresentação Drupal.
- **Motivo:** a documentação do tema divergiu do código e o acúmulo de templates e instruções legadas dificulta compor o site com UI Suite.
- **Referências:** [recomendações oficiais UI Patterns 2](https://project.pages.drupalcode.org/ui_patterns/2-authors/2-best-practices/), [autoria de componentes](https://project.pages.drupalcode.org/ui_patterns/2-authors/0-authoring-a-component/), [presenter templates](https://project.pages.drupalcode.org/ui_patterns/1-users/5-presenter-templates/), [stories e Library](https://project.pages.drupalcode.org/ui_patterns/2-authors/1-stories-and-library/), [release UI Patterns](https://www.drupal.org/project/ui_patterns/releases).

## Decisão

1. SDC é o contrato visual do tema. Cada componente novo deve incluir schema, Twig, assets necessários e ao menos uma story descoberta pela UI Patterns Library. A UI Patterns Library é a fonte única para o catálogo de SDCs/stories. Por decisão posterior do responsável em 2026-11-13, `aculta_ui_library` foi removido por completo, inclusive a rota de compatibilidade; manter somente `ui_patterns_library`.
2. Props carregam dados simples, tipados e necessários à apresentação; slots recebem conteúdo renderizável do Drupal. Não passar render arrays por props, nem criar prop drilling para filhos/renderables que podem ser slots. Slots são opcionais e devem tolerar qualquer conteúdo renderizável; não testar tipo de prop em Twig nem aplicar filtros dependentes de estrutura a slots. Props obrigatórias devem ter fallback seguro no template. Manter slots independentes; não indexar uma lista de slots a partir de outra. Usar a prop type `links` para menus, breadcrumbs, links e paginação. Componentes permanecem independentes, usam variants para diferenças visuais do mesmo modelo (não props que imitam variants), declaram default funcional e preferem nomes de variants alinhados aos modificadores de markup. Evitar combinações de props impossíveis, IDs fixos e contexto Twig implícito.
3. Usar a integração UI Patterns correspondente somente quando necessária: Blocks para blocos configuráveis; Layouts para seções do Layout Builder; Field Formatters para campos; Views para row/style/display. A escolha de integração não transfere consulta, autorização, acesso, cache ou regras de conteúdo ao tema.
4. Preferir construtores de display do Drupal para entidades e Views. Um presenter template pode permanecer como adaptador leve quando não há construtor apropriado, por exemplo no shell da página ou em menus. Não converter templates mecanicamente em SDCs.
5. Os metadados devem usar nomes agnósticos ao negócio quando o componente for reutilizável; peças internas devem ser identificáveis como internas, agrupadas e com slots `expected` quando a API instalada suportar. Stories devem exemplificar estados úteis sem listas artificiais de renderables. Twig deve usar `attributes` no wrapper, loopar slots com proteção para renderable unitário/lista e ser lintado. `include()` explícito é a opção para dependências inevitáveis entre componentes.
6. O corte legado será orientado por consumidores comprovados no código e Config Sync. Documentação e roadmaps devem refletir o checkout antes de planejar remoções. Migrações ocorrerão em lotes revisáveis com critérios de saída, validação de acesso/cache e evidência de renderização.
7. O tema mantém um shell único e as cinco regiões declaradas atualmente. A opção e o template paralelo `classic`/`v2` estão removidos do código-fonte. O no-op temporário do hook de sugestões foi removido após rebuild do cache do Runtime em 2026-11-14; nenhuma variante permanece como configuração ou contrato do tema.

### Decisões de escopo confirmadas pelo responsável

- SDC sem consumidor será candidato a remoção somente se não estiver publicado/selecionável em UI Libraries, não tiver consumidor no código/configuração e não houver plano aprovado. SDCs que integrem UI Libraries são preservados. Todo item oferecido pelas UI Libraries deve ser implementado como SDC; itens não SDC devem ser convertidos ou retirados do catálogo. Todo SDC mantido e todo SDC novo recebe story.
- Renomear componentes somente quando representarem um conceito reutilizável cujo nome atual está preso a domínio. Respeitar referências persistidas; preparar migração/compatibilidade antes da mudança.
- O alvo é tentar remover todos os templates atuais. No corte revisado em 2026-11-14, 17 permanecem após migrações comprovadas para SDCs/UI Patterns e remoção de adapters sem consumidor. Primeiro procurar substituição por entity display, Layout Builder, Views, Field Formatter, Block ou SDC chamado pelo render array. Só permanecerá um presenter mínimo quando o Drupal/UI Patterns exigir o theme hook e não houver display builder equivalente. Não remover contratos Core/HTMX/Forms sem substituto funcional.
- **Revisão posterior (2026-11-13; estado conferido em 2026-11-14):** primeiro, catálogo e prévias próprias de blocos foram retirados de `aculta_ui_library`; depois, o responsável determinou remover o módulo e seu redirect. O Config Sync e o Runtime não habilitam o módulo, que já não possui código executável, rota ou gate próprio no checkout. Os documentos residuais foram removidos. A UI Patterns Library oficial permanece habilitada. O Runtime descobriu 148 SDCs antes da purga; o checkout atual contém 145 e requer rebuild de cache. Resta limpar uma chave órfã de `system.schema` no Runtime com backup e prova de restauração. O gate de contrato continua exigindo stories e que só a Library oficial esteja habilitada.

## Relação com decisões anteriores

Esta ADR complementa a decisão vigente de corte radical da ADR-054: especifica como aplicar as recomendações oficiais UI Patterns 2 e exige reconciliação documental antes de priorizar novos lotes. Trechos antigos dos planos que determinam shell paralelo ou homologação visual como pré-condição estão superados. Preserva Layout Builder nos displays compatíveis, as cinco regiões do shell, os contratos da ADR-053 e as fronteiras entre tema e Portal. Não autoriza importação de configuração, migração estrutural ou operação de Runtime.

## Estado verificado no código e Config Sync

Primeira leitura realizada em 2026-11-13; métricas e estado do checkout
atualizados em 2026-11-14:

- `aculta420_v2.info.yml` declara as regiões `institution`, `header`, `content`, `sidebar_first` e `footer`; `templates/layout/page.html.twig` é o shell de página encontrado no checkout.
- O Config Sync habilita UI Patterns, Blocks, Field, Field Formatters, Layouts, Library e Views; também habilita UI Styles, integrações de Block, Layout Builder, Page, UI Patterns, Views e Entity Status. `ui_patterns_library` está habilitada no Sync e no Runtime. `aculta_ui_library` está ausente de ambos; o Runtime conserva apenas uma chave órfã em `system.schema`, pendente de limpeza focal e backup comprovado.
- Após a purga do seletor em 2026-11-14, o tema contém 145 manifests SDC e 230 arquivos de story. Cada SDC possui ao menos uma story; `hint` tem exemplos normal/muted, e `sales-panel`/`secret-reveal` têm composições demonstrativas com dados fictícios.
- A release estável mais recente verificada é UI Patterns 2.0.23 (13/10/2026), compatível com Drupal 10.6/11.3/12. O lock usa `dev-2.0.x` no commit `a7e9c28c522a5b0c8b71c731cab5482d60164e1e`, idêntico à tag estável 2.0.23. O histórico confirma que a constraint dev foi adotada em 2026-11-03 para compatibilidade antecipada com Drupal 12 e ao mesmo tempo foi adicionado o patch ACULTA que substitui quatro chamadas depreciadas de `drupal_static()`. A release atual absorveu o requisito de Core 12; o patch local continua necessário enquanto upstream não resolver a depreciação. Avaliar constraint estável `^2.0` mantendo o patch, sem atualizar dependências nesta etapa. A Library 2.0 ainda usa templates `hook_theme`; a documentação oficial prevê migração para SDC/display building em 2.1 ou 2.2, então os quatro overrides precisam de gate de compatibilidade.
- Restam 17 templates Twig Drupal no tema em 2026-11-14, todos relacionados na fila P3 do roadmap do tema; templates internos dos SDCs não entram nessa contagem.
- O controller upstream da UI Patterns Library itera as definições agrupadas do component plugin manager para construir o catálogo do provider; não foi identificado filtro upstream para excluir SDCs individuais. O inventário CSV atual tem 451 linhas: cabeçalho e 450 consumers, incluindo 145 definições SDC. O detector encontra referências literais de produção a 110 SDCs e não encontra a 35. A varredura inclui composição entre SDCs e exclui stories, testes e arquivos do próprio componente; ainda não reconhece IDs dinâmicos nem prova ausência de consumidor editorial/runtime. Conforme decisão do responsável, as definições existentes não serão removidas apenas pela contagem literal. O inventário está em [ui-suite-consumidores-iniciais.csv](../architecture/inventarios/ui-suite-consumidores-iniciais.csv), gerado por `scripts/inventory-ui-suite-consumers.php`.
- Documentos históricos mantêm métricas de snapshots antigos (127/188), agora identificadas como históricas em alguns roadmaps; a auditoria por domínio e a matriz de consumidores ainda precisam ser completadas com displays, Views, chamadas PHP/Twig e stories. A configuração do seletor classic/v2 foi retirada do checkout; o hook temporário de compatibilidade foi removido após reconstrução do cache Drupal em 2026-11-14.

## Estado e próxima ação

P0 teve a primeira passada, reconciliada com o checkout em 2026-11-14: contagens atuais, histórico da constraint UI Patterns, comportamento da Library e decisão de remover o módulo customizado. P1 ganhou stories para todos os SDCs, títulos para todas as props de topo e descrições para todos os slots. A remoção do SDC/rota separados do seletor mantém acesso, token CSRF e dados no módulo Fórum; a Barra de Reações mantém sua paleta integrada. Faltam confirmar dados editoriais persistidos no Runtime e concluir a auditoria semântica dos contratos. O inventário inicial de consumidores não equivale ao cruzamento completo de SDCs internos/dinâmicos nem comprova Runtime. Próximo: cruzar os 145 SDCs com os consumidores reais e revisar os presenters restantes por domínio. A desinstalação do módulo segue dependente de janela estrutural Runtime. O roadmap do tema é a fila executável; só marcar migrações como concluídas com referência a código/configuração e evidência.

### Props sem tipo de integração UI Patterns

O `ComponentDefinitionAnnotator` usa `unknown` quando nenhum prop type ou adapter
compatível é encontrado. O `SourcePluginManager` não oferece fontes para esse
tipo. Isso não invalida o SDC para renderização por código, mas impede configurar
essas props no formulário UI Patterns.

**Correção P1 confirmada:** `account-menu.legal_links` e
`events-upcoming-block.items` agora usam `$ref: ui-patterns://links`. Em consulta
ao provider sem cache de definições, ambas foram anotadas como `links` e cada uma
encontrou duas Sources. A descoberta das Sources também emitiu seis warnings de
Core `EntityReferenceItem.php:782` (`handler_settings` ausente); registrar e
investigar a configuração/detector de Sources antes de aprovar a experiência de
edição no Runtime. O formato atual `title/url` dos dados dos dois consumidores
permanece compatível.
