# Prompt de execução - Agente CLI ACULTA

Você é o agente de implementação no Runtime Drupal do ACULTA, branch `dev`, repositório `https://github.com/coletivo420/aculta`. Implemente integralmente o plano `PLANO-CORTE-DIRETO.md` contido neste pacote, usando `input/private_message-4.0.0-alpha5.tar.gz`, `staging/ready`, `staging/manual`, `staging/PORT-MANIFEST.json` e o código atual do repositório. Leia as instruções e skills locais antes de começar. O objetivo é incorporar o Private Message 4.0.0-alpha5 ao módulo existente `web/modules/custom/aculta_portal/modules/aculta_messenger`, removendo o contrib de vez.

**MUDANÇA FUNDAMENTAL:** está autorizado o **descarte completo e definitivo dos dados legados exclusivos do Private Message** (mensagens, threads, membros, leituras, bloqueios e históricos), sem conversão, preservação, compatibilidade, transferência de provider/schema instalado ou migração de linhas. Use **instalação limpa** dos entity types e tabelas sob provider `aculta_messenger`. Preserve, entretanto, todos os dados compartilhados e de módulos não PM: usuários, avisos gerados por outros módulos, preferências compartilhadas, filas transversais, `aculta_mailer`, conteúdos de Fórum/LMS/Wiki/etc. Não confunda corte de dados PM com exclusão geral de notificações.

Execute em ordem:

1. **Git e ambiente:** registre HEAD de `dev`, git status, patches, Core/Drush/PHP/Composer, estado dos módulos e do banco. Não faça reset de trabalho alheio; commits seletivos e push direto em dev somente se permitido e com gates aprovados.
2. **Inspeção:** confronte código do contrib instalado, tar upstream e staging. Encontre todas as referências, providers, field definitions, bancos, services, dependencies, hooks, permissões e efeitos reais do `hook_uninstall`/rotinas de exclusão do contrib. Leia `PORT-MANIFEST.json`, que informa colisões. O lint antigo não vale como homologação do porte.
3. **Isolamento:** crie backup do banco/config/arquivos privados, valide restauração num clone e execute nele a primeira passagem. Suspenda web writes, cron e workers durante o corte. Se não houver clone/backup restaurável, **não faça purge ou uninstall no Runtime real**; continue as alterações de código e entregue bloqueadores.
4. **Classificação de dados:** gere inventário verificável classificando cada tabela, entidade, field, config, fila, aviso e correlação como DESCARTAR_PM, MANTER_ACULTA, MIGRAR_CONFIG_FUNCIONAL ou INVESTIGAR. Resolva INVESTIGAR antes de purgar. Nunca truncar `message`, `message__*`, usuários ou tabelas compartilhadas. Avisos especificamente vinculados a mensagens privadas antigas só podem ser excluídos por filtro comprovado (p.ex. origem `field_aculta_messenger_source_pm`), conferindo dependentes.
5. **Portar fonte:** integre classes, interfaces, handlers, plugins, controllers, forms, JS, templates, YAML e testes do `staging/ready`, mesclando manualmente `staging/manual`. Corrija namespaces, autoload, plugin discovery, hook owner, services, assets e dependências sem sobrescrever funcionalidades existentes do Messenger. Não copiar o instalador e uninstall do contrib cegamente; não ativar `private_message_notify` nem segundo inbox; resolver `browser_notification` órfão. Conserve GPL/créditos.
6. **Cutover limpo:** implemente procedimento idempotente com `inventory`, `dry-run`, `purge-legacy`, `verify-empty`, `bootstrap-new`, protegido contra execução acidental/produção. Em clone, remova dados PM por Entity API ainda sob contrib; verifique escopo e contagens; desinstale o contrib por sequência suportada do Core após inspecionar efeitos. Evite `drush pm:uninstall` automático, SQL indiscriminado ou edição direta de `core.extension`. Remova schema/definições residuais PM apenas por mecanismo seguro. Instale tipos e schemas vazios sob novo provider, incluindo histórico de leitura próprio se necessário. Garanta que reexecução não apague novas mensagens.
7. **Eliminar contrib:** retire `drupal/private_message` do Composer e lock, dependências em `.info.yml`, config sync e referências ativas. Execute Composer validate e Drush bootstrap/CR. IDs técnicos de entidade/evento/serviço podem permanecer quando necessários como contratos internos, mas extensão `private_message` não pode ser exigida.
8. **Integração e segurança:** manter acesso por participantes, restrição na criação, bloqueio bilateral, flood/locks, CSRF, XSS, cache por usuário, retenção (padrão já adotado pelo projeto), API/eventos dos avisos e idempotência. E-mails privados são avisos sem corpo e pelo `aculta_mailer`; sem duplicações. Use drawer multidomínio, ACCOUNT para conversas, MAIN para administração `/painel-administrativo/aculta/mensagens`, UI Suite/SDC e modos claro/escuro.
9. **Testes:** implemente e execute testes de banco legado populado e vazio; verifique nenhum registro PM herdado e preservação de avisos não PM; execute Unit, Kernel/MariaDB, Functional, Playwright, lint, PHPCS, PHPStan nível 10 com baseline do projeto, Semgrep e smoke tests em todos os purposes. Registre comandos/logs/contagens e discrimine limitações reais. Não modifique baseline para esconder regressões.
10. **Documentação/entrega:** atualize arquitetura, integrações, módulo README, changelog, ADR/plano/skills/guardrails pertinentes e relatório final (HEAD inicial/final, arquivos alterados, comandos, backup/teste de restore, evidências, SQL counts, provedores, estado de Composer, testes, pendências). Faça commits por conjuntos coerentes, `git add` somente nos arquivos próprios, `git push origin dev` apenas após gates. Não alegue deploy sem efetivamente executá-lo.

**GATE DE BLOQUEIO:** qualquer dúvida sobre propriedade de dados, ausência de backup testado ou efeitos colaterais de uninstall = abortar SOMENTE operação destrutiva no Runtime, sem interromper refatoração segura de código, documentação e testes. Nenhum usuário pode perder dados não PM. Todos os registros legados exclusivos do PM podem ser descartados após esses gates; não implementar migração deles.

Entregue ao final relatório técnico com checklist realizado e pendências, comandos executados, evidências, SHA/HEAD e estado real de `origin/dev`.
