# ADR-057 — perícia inicial P05 (2026-11-17)

**HEAD de referência:** `da4c8f01d`.
**Escopo:** inspeção estática do pacote/lock/config Sync e conferência de metadados upstream. Sem instalação, alteração de Composer, Config Import, operação Runtime ou teste em conteúdo.

## Pacotes e estado local

O `composer.lock` rastreado declara `drupal/ui_patterns_field_group` em `dev-2.0.x`, referência `4403e7b0e27679f47113e96fcdc5349c95e164d1`; `drupal/field_group` está em `4.1.0-beta1`; `drupal/ui_patterns` aponta para `a7e9c28c522a5b0c8b71c731cab5482d60164e1e`. O módulo de integração não aparece em `config/sync/core.extension.yml`; UI Patterns Field Formatters está habilitado no Sync. Estado Runtime do módulo não foi consultado nesta fase.

O `ui_patterns_field_group.info.yml` instalado declara `core_version_requirement: ^9 || ^10 || ^11`. A página upstream informa que `2.0.0-beta2` só declara Drupal ^9/^10/^11 e que o projeto **não é coberto pela política Drupal Security Advisory**. [Projeto UI Patterns Field Group](https://www.drupal.org/project/ui_patterns_field_group)

A página do Field Group lista `4.1.0-beta1` como compatível com ^10.3/^11 e diz que **releases estáveis** do projeto são cobertas pela política de segurança; o lock usa beta, não o release estável coberto. [Projeto Field Group](https://www.drupal.org/project/field_group)

Revalidação upstream em 2026-11-17: o projeto do adapter ainda declara que não é coberto pela política de advisories, e a release beta mais recente continua limitada a Drupal 11. No Field Group, a issue [#3598196 — ajustes automáticos de compatibilidade Drupal 12 para 4.x-dev](https://www.drupal.org/project/field_group/issues/3598196) aparece como **Needs review**; não há release compatível com Drupal 12 publicada. O suporte Drupal 12 do UI Patterns principal não se propaga a essas integrações separadas.

UI Patterns principal tem release 2.0.23 declarado para Drupal ^10.6/^11.3/^12; isso não estende automaticamente o suporte às dependências separadas Field Group e UI Patterns Field Group. [Releases do UI Patterns](https://www.drupal.org/project/ui_patterns/releases)

## Revisão estática do adapter

`ComponentFormatter::preRender()` entrega contexto de entidade, bundle, configuração de Field Group e render array dos filhos para o builder do componente. `FieldGroupChildSource::getPropValue()` devolve diretamente o filho configurado como slot. O pacote tem testes upstream Unit e FunctionalJavascript, mas não foi executado nesta inspeção e não existe prova local de integração dos consumidores do Portal. A leitura do código não prova, por si só, preservação de acesso/cache/tradução/revisão dos render arrays no contexto real do ACULTA.

## Decisão do gate P05

**BLOCKED_UPSTREAM para integração/habilitação:** o adapter necessário está fora da política de advisories e declara suporte até Drupal 11; o Field Group instalado é beta, também sem declaração Drupal 12. Não há base para declarar o gate estrito de segurança/compatibilidade aprovado nem para habilitar/importar o módulo. Manter UI Patterns Field Formatters/SDC como fallback temporário, sem alterar o Config Sync.

Para reabrir P05: obter upstream compatível com Drupal 12 e cobertura de segurança apropriada para o adapter (ou produzir alternativa própria auditável), fazer revisão independente R2, executar o piloto de Revista/Wiki em ambiente descartável e provar acesso/cache/tradução/revisão antes de qualquer integração configurada. A divergência Runtime/Sync permanece **DEFERRED**; nenhuma leitura autenticada do Runtime foi feita aqui.

## Auditoria adicional do código e da dependência — 2026-11-18

O checkout confirma o pacote em `4403e7b` (tag `2.0.0-beta2`) e as dependências
reais: `drupal/field_group` 4.1.0-beta1 e UI Patterns 2.0.23. O `composer.json`
do adapter requer UI Patterns `^2`; o `info.yml` continua declarando Core
`^9 || ^10 || ^11`, apesar da release beta2 anunciar melhorias de
compatibilidade Drupal 12. Isso deixa suporte Drupal 12 **não declarado pelo
módulo instalável**. A release beta2 também é a única versão publicada no
canal 2.x e o projeto continua sem cobertura de advisories.

Na leitura do adapter, `ComponentFormatter::preRender()` incorpora as
propriedades do render array original e o render array `component`;
`FieldGroupChildSource::getPropValue()` devolve o filho selecionado sem
serializá-lo, preservando a oportunidade de a Render API processar acesso e
cacheabilidade. `FieldGroupLabelSource` escapa texto simples e usa
`Xss::filterAdmin()` quando a opção de label como HTML está ligada. Essa
inspeção não prova o resultado final de acesso/cache nos consumidores ACULTA;
os testes upstream de renderização e configuração também definem
`strictConfigSchema = FALSE` e não cobrem os contratos de revisão, tradução,
acesso por papel ou export/import exigidos pelo piloto.

O commit de UI Patterns fixado no lock resolve a preocupação de segurança do
projeto principal: o checkout está na tag 2.0.23, enquanto o advisory oficial
SA-CONTRIB-2026-075 afeta `>=2.0.0 <2.0.17`. Este advisory **não** cobre nem
certifica o módulo Field Group separado, que continua explicitamente fora da
política. Referências: [advisory do UI Patterns](https://www.drupal.org/sa-contrib-2026-075),
[releases do UI Patterns Field Group](https://www.drupal.org/project/ui_patterns_field_group/releases)
e [política de segurança do projeto](https://www.drupal.org/project/ui_patterns_field_group).

**Conclusão P05 mantida: BLOCKED_UPSTREAM.** A inspeção é estática; nenhum
teste do adapter foi executado, nenhum módulo foi habilitado e nenhum
componente/configuração/Runtime foi alterado. Retomar a fase B exige release
com suporte Core 12 declarado e solução aceitável para cobertura de segurança,
depois revisão independente e sandbox isolado conforme a ADR.
