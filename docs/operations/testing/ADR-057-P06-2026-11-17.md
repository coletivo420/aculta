## Auditoria autenticada Wiki/Cursos — contribuição P06

`tests/browser/transversal/aculta-papeis/papeis.mjs` foi executado no Runtime
de desenvolvimento autorizado, com Firefox, acessos somente GET e as contas
locais `teste_wiki` e `teste_educador`. A execução contra o CSS servido atual
passou nos cursos e detectou overflow em `/we-sativa` a 320 px nos dois temas;
no formulário escuro encontrou contraste insuficiente nas abas verticais.

O overflow vinha da coluna implícita do grid da área Wiki, cujo tamanho mínimo
intrínseco era 479 px mesmo dentro de uma coluna de 288 px. O formulário não
carregava `color-mode-dark.css`, que estava anexado apenas à UI Library; com a
folha ativa, a regra do Core para o título da aba selecionada ainda exigia
especificidade maior. As correções locais limitam o grid a
`minmax(0, 1fr)`, carregam o suporte escuro junto ao estilo global e cobrem o
título selecionado.

Para validar essas alterações antes de serem servidas, a matriz Firefox foi
repetida nas quatro rotas, claro/escuro e 320/1440 px, injetando no navegador
as duas folhas CSS atuais da worktree. Resultado: **16/16 PASS**, HTTP 200,
sem overflow e sem violações axe de contraste. Essa matriz testa o candidato
local sobre o Runtime; não prova que o Runtime já serve as alterações por sua
biblioteca Drupal.

Leitura adicional dos assets públicos: o SHA-256 de
`/themes/custom/aculta420_v2/src/styles/color-mode-dark.css` no host MAIN é
`1b3e201112ba9d9c0b477d2402afb8cca0d5c208017b60ab5717545c1ed8cd07`, igual ao
arquivo local. Porém, os CSS agregados linkados pela home não contêm o novo
seletor `.vertical-tabs__menu-item.is-selected`; portanto, a fonte está no
docroot público, mas a página ainda recebe uma agregação antiga. Não foi feito
clear de cache nem reconstruída a agregação. A confirmação da biblioteca global
no HTML renderizado permanece **DEFERRED** até uma operação autorizada de
rebuild; o SHA do Runtime Drupal/PHP continua sem verificação.

Gates do diff CSS: Stylelint PASS; `validate-aculta420-v2-foundations.php`
PASS (85 pares de contraste); `validate-aculta420-ui-styles.php` PASS (54);

## Nota de execução

A invocação diagnóstica inicial usou os padrões do script antes de identificar que ele também fazia login de teste na Conta e abria a UI Library administrativa. Esses fluxos de autenticação não foram autorizados pela escolha de validação somente por leitura. O helper submeteu os formulários de login e criou sessões de teste; não houve submissão de edição nem alteração de conteúdo/configuração. As capturas locais dessa invocação foram removidas. A sessão HTTP de teste pode permanecer no Runtime até expirar; não foi feita limpeza/logout automatizado. As rodadas subsequentes desativaram explicitamente autenticação e UI Library.

**P06: PARCIAL.** O smoke público multihost passou e a frente autenticada
agora tem cobertura reproduzível e uma correção local validada por overlay.
Ainda falta sincronizar e verificar o CSS servido após os gates P00; snapshots,
aceite visual humano, teclado/leitor de tela e autorização negativa para
outros papéis continuam pendentes.
