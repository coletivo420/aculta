# ADR-057 — baseline parcial P07 (2026-11-17)

## Escopo e método

O runner reutilizável `tests/browser/transversal/aculta420-v2-audit-2026-11/performance.mjs`
faz navegação pública sem login, uma navegação fria e reload quente no mesmo
contexto, nos dez hosts de desenvolvimento registrados em
`docs/architecture/multidomain.md`. Mede TTFB, DOM Ready, load, paint, LCP,
CLS, long tasks e requests/tamanhos declarados pelo navegador em Firefox e
Chromium, 390/1440 CSS px e claro/escuro. Também tenta uma interação de menu
em viewport móvel. O script grava os dados completos em `SUITE_OUT`, fora do
Git. Agora registra `null` quando o browser não suporta uma API de medição;
as duas engines desta rodada suportaram LCP, CLS, long tasks e Event Timing.

## Resultados

| Execução | Cobertura | Resultado |
| --- | --- | --- |
| Firefox 142.0.1 | 10 hosts × 2 larguras × 2 temas × frio/quente = 80 navegações | 80 HTTP 200; zero falhas; CLS 0 em todos os registros |
| Chromium 141.0.7390.37 | 10 hosts × 2 larguras × 2 temas × frio/quente = 80 navegações | 80 HTTP 200; zero falhas; seis registros com CLS > 0,1, todos no MAIN |

Na matriz Firefox, a mediana agregada de LCP foi 1.054 ms a frio e 882 ms a
quente; load foi 1.214 ms e 941 ms, respectivamente. No Chromium, LCP foi
medido em 74/80 registros; a mediana desses registros foi 918 ms a frio e
684 ms a quente; load foi 1.073 ms e 664 ms. Na matriz Chromium, CLS mediano
foi 0,0002 e p75 0,0094; o máximo foi 0,5803. Os seis registros acima de 0,1
foram no MAIN, em ambos os viewports e estados de cache; os outros nove hosts
ficaram abaixo de 0,044. O log de recursos MAIN Firefox (390 px, claro, frio)
registrou por Resource Timing 3 CSS, 16 JS, 3 imagens e 4 fontes:
20.101 bytes transferidos de CSS, 107.787 de JS, 118.529 de imagens e 70.328
de fontes. As respostas de CSS/JS informaram gzip; esses tamanhos variam por
contexto/cache e não são budgets aprovados.

O Chromium registrou até duas long tasks em navegações frias, com duração
máxima de 52–62 ms nas amostras MAIN, e duração Event Timing da interação de
menu de 16–24 ms no MAIN móvel. Isso é uma amostra sintética de uma interação,
não INP de campo. O runner não possui amostragem CrUX/RUM nem atribui
prioridade real ao LCP.

## Achado de estabilidade visual

O CLS Chromium excede o limite de referência da ADR-057 (`<= 0,1`) no MAIN.
No viewport móvel, no frio,
o maior deslocamento move `.page__showcase` de `y=515` para `y=143` e faz o
`main#main-content` aparecer no fluxo; no quente, o mesmo bloco salta de
`y=515` para `y=149`. A provável relação é a ativação tardia de
`.navigation-bar.has-js`: `navigation-bar.js` adiciona essa classe durante a
inicialização, e `navigation-bar.css` então posiciona o painel como `fixed`,
retirando-o do fluxo do grid. A associação é compatível com os retângulos
capturados, mas ainda precisa de experimento causal antes de orientar uma
correção. Um segundo deslocamento frio também inclui o botão de navegação e
coincide com mudança dimensional após carregamento de fontes.

Firefox reportou CLS zero no mesmo site e matriz, com suporte confirmado da API
de layout shift. A diferença entre engines exige conservar as entradas de
layout shift e validar a métrica em Chromium. Nenhuma alteração de produto foi
feita com base apenas nesta coleta.
